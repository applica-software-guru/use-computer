use-computer executes input on a screen for computer-use agents, moving the mouse, clicking, double-clicking, right-clicking, dragging, scrolling, typing text, pressing key combinations, and capturing a screenshot of the current screen. It is the acting half of a pair, since ui-locator answers where the Invia button is and returns pixel coordinates while use-computer performs the click there, and both are driven by another AI agent through a CLI that emits JSON on stdout and diagnostics on stderr, with a Python API underneath. Two interchangeable backends sit behind one interface, where local drives the display of the machine it runs on and vnc drives a remote framebuffer over RFB, and a backend is chosen by a named profile in a project-local config file so that adding one is configuration rather than code. Backends normalise a single key-name syntax, so one spelling of a shortcut works on both, and each reports its own coordinate space and screen size. Three problems define the design. First, coordinate spaces, because a screenshot on a HiDPI display is larger than the space the operating system clicks in, so every coordinate carries the space it belongs to and use-computer scales between screenshot pixels and actuation units and refuses to guess when the ratio is unknown, since an unhandled factor of two makes every click land in the wrong place. Second, setup cost, because opening a VNC connection dominates a single action, so one run accepts a batch of actions and performs them over one connection. Third, blind actuation, because a click that lands on nothing looks exactly like a click that worked, so an action can compare a screenshot taken before and after and report whether the screen actually changed, which gives the calling agent the feedback signal it needs to correct a stale coordinate instead of retrying forever. Since it types real keystrokes and moves a real pointer it is safe by construction, with a dry-run mode that resolves and logs actions without performing them, per-action delays and a typing rate that applications do not drop characters from, an explicit opt-in for the local backend, and a clear error when the host denies the accessibility or screen-recording permission a backend needs rather than silently doing nothing. The stack mirrors my ui-locator project and all code lives under code in a src layout at code/src/use_computer. Python 3.10 or newer with 3.12 as the runtime, uv for dependencies and builds with uv.lock left uncommitted so that CI resolves the way a user installing from PyPI does, hatchling as the build backend, pydantic 2 for every data model with frozen result models, pydantic-settings for configuration under the USE_COMPUTER env prefix, typer 0.16 or newer and never 0.12, rich 13 or newer for terminal output, pillow for screenshots, python-dotenv for env layering, and tomli only below Python 3.11. Backends are optional extras imported lazily so the package installs without them, where the local extra uses pynput 1.8 or newer for input and mss 10 or newer for capture in preference to pyautogui whose last release 0.9.54 dates from 2023, and the vnc extra uses vncdotool 1.3 or newer, which provides move, click, key, type and capture over RFB. Tests use pytest and pytest-mock with a fake backend that records the actions it was asked to perform, linting is ruff at line length 100 selecting E, F, I, UP, B, SIM and C4 with B008 ignored in the cli module for typer idioms, and typing is mypy in strict mode. Carry over these patterns from ui-locator. A runtime-checkable Protocol that every backend implements, covering screenshot, move, click, drag, scroll, type_text and key, whose construction raises a BackendNotAvailableError naming the extra to install. A project root discovered by walking up from the current directory the way git finds its own, namely a .use-computer directory holding a committed config.toml and a gitignored .env, with XDG fallbacks that use the config and data directories and never a cache directory. Named backend profiles in that config, selected with a use flag. Configuration precedence from highest to lowest of CLI flags, environment variables, .env files, the selected profile, top-level config keys, the global config and then field defaults, together with a config show command that prints every resolved value and the layer it came from, naming the exact environment variable and masking secrets, and that warns on stderr about unknown keys including keys inside profiles that are not selected. A skill for the calling agent bundled as package data inside the package at code/src/use_computer/skill/SKILL.md rather than at the repository root, or it will not ship in the wheel, exposed through a skill command with install, update, remove and status subcommands, a scope flag accepting user, project, agents or claude, and a dir flag, where the project scope follows the layout the target project already uses and defaults to the neutral .agents/skills when neither exists, install refuses to overwrite without force, and neither install nor remove ever touches a directory that does not carry this skill frontmatter marker. A single CLI with a default command implemented by rewriting argv in the console-script entry point so a bare action works alongside subcommands, never by subclassing TyperGroup, because typer 0.27 stopped being click-based and that approach breaks silently. JSON printed with plain json.dumps rather than through rich, because rich soft-wraps long strings and can emit a newline inside a JSON string, with all diagnostics on stderr and exit codes of 0 for success, 1 for failure and 2 for bad usage. A GitHub Actions workflow that tests a matrix over both ends of the supported typer range, then builds, then uploads to PyPI when a release is published, gated on the git tag matching the version in pyproject.toml and on the bundled SKILL.md being present in the wheel, and preferring Trusted Publishing over a long-lived token. Also record these conventions, each of which cost real debugging in ui-locator. Never import a transitive dependency without declaring it, which is how an undeclared click import survived until typer dropped click. Declare a dependency floor that is actually tested and verify it in CI. In tests strip ANSI escapes from CLI output and pin TERM and COLUMNS, because rich enables colour inside GitHub Actions and its highlighter splits an option token across styled spans, so substring assertions pass locally and fail on CI. Isolate the test environment from ambient USE_COMPUTER, CLAUDE and XDG variables and from any project root above the checkout.
